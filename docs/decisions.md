# Журнал решений

Формат: дата — решение — почему — какие были альтернативы — статус (принято / гипотеза, проверяется на этапе X).

---

### 2026-11-03 — Магнитола Toyota как панель управления, а не как источник звука
**Почему:** штатный вид, физические кнопки и крутилки. CD/MD-механизмы и родная электроника не нужны, P8 и так используется 100% времени.
**Почему ещё:** главная мотивация проекта — удобная физическая крутилка громкости. Сенсорная aftermarket Nakamichi на ходу неудобна.
**Альтернативы:** своя панель с нуля (как в видео Garage Tinkering) — больше работы с механикой и внешним видом.

### 2026-11-03 — Микроконтроллер ESP32-S3
**Почему:** BLE 5 (на случай, если P8 примет BLE-клавиатуру), Wi-Fi (веб-настройка, OTA), много GPIO, встроенный USB.
**Альтернативы:** ESP32-C3 (мало ног), RP2040 (нет BLE/Wi-Fi без доп. модуля).

### 2026-11-03 — Прошивка: PlatformIO + Arduino (C++)
**Почему:** большая экосистема (NimBLE, VEML7700, веб-сервер, OTA), быстрый старт. При необходимости можно точечно спуститься в ESP-IDF.
**Альтернативы:** ESP-IDF (больше кода), MicroPython (неудобен для BLE HID), Rust esp-rs (BLE HID менее зрелый).

### 2026-11-03 — Яркость P8 через «подсветку» его датчика светодиодом
**Почему:** датчик P8 закрыт корпусом навигации, оптическая трубка пропускает слишком мало света (проверено). Сама автояркость P8 хорошая — много ступеней (проверено до установки в корпус), её стоит использовать, а не заменять. Корпус изолирует датчик от внешнего света и от света экрана (проверено), а автояркость отрабатывает свет на датчике плавно, с реакцией 1–2 с (проверено фонариком) → светодиод даёт полный контроль. Официального способа управлять яркостью извне не найдено.
**Детали:** внешний датчик VEML7700 → кривая → ШИМ (высокая частота + RC-фильтр). Белый/зелёный светодиод, не ИК. Изоляцию датчика от света экрана (её уже даёт корпус) при монтаже не нарушать: иначе положительная обратная связь (экран ярче → датчик светлее → экран ещё ярче).
**Альтернативы:** вытащить датчик на световод к лицевой панели — внешний свет в салоне не совпадает с тем, что нужно глазам, и нет ручной поправки.
**Статус:** принято (основа проверена на этапе 0.3); кривая — на калибровке 1.4.

### 2026-11-03 — ~~Управление P8 через имитацию пульта AC-44F6 (BLE)~~ — заменено
**Почему:** проводного входа для кнопок руля у P8, по-видимому, нет (не подтверждено). Родной пульт беспроводной.
**Запасной план:** ESP32 «нажимает» кнопки разобранного родного пульта через оптопары/транзисторы.
**Статус:** отменено после этапа 0.1 — пульт, скорее всего, не Bluetooth. См. запись «Перехват и повтор радиоканала пульта».

### 2026-11-03 — Ночной режим Android Auto не трогаем
**Почему:** решение «день/ночь» принимает прошивка P8 внутри протокола AA. Извне не подменить без взлома прошивки. P8 ночной режим сам не переключает, в меню пункта нет, от датчика он не зависит (проверено).
**Не подходит:** переключать тему телефона целиком — затронет телефон вне машины.
**Что остаётся:** настройка «день/ночь для карт» внутри приложения Android Auto (только экран AA, проверить); HID-код у P8 (этап 1.7, маловероятно); если нет — обновление прошивки P8 / поддержка ATOTO (этап 1.12); в крайнем случае вручную Night/Day в настройке AA.
**Статус:** принято; варианты выше проверяются на этапах 0.4 и 1.7.

### 2026-11-03 — Порядок работы: телефон → ESP32 на столе → магнитола
**Почему:** магнитолу из Японии ждать месяцами. Всю логику прошивки можно проверить на макетке с энкодерами и кнопками.
**Детали:** параллельно искать магнитолу на Кипре — там много б/у японских машин (разборки, Bazaraki): может оказаться быстрее и дешевле Японии.

### 2026-11-03 — Всё в git-репозитории, без Claude Project
**Почему:** единый источник правды для кода, документации и результатов реверса. Claude Code работает с репозиторием напрямую, контекст — в `CLAUDE.md`.

### 2026-11-03 — Свой APK для этапа 0 — только при необходимости
**Почему:** готовые приложения (nRF Connect, эмулятор BT-клавиатуры) должны ответить на вопросы этапа 0. Свой APK — лишняя работа, если дальше всё равно ESP32.
**Когда писать:** если готовых не хватит (например, нужно точно повторить Report Map пульта со смартфона).

### 2026-11-03 — Обратная связь о режимах важнее, чем казалось; временно — без LCD
**Почему:** без LCD не видно, в каком режиме меню находится панель (громкость / яркость / обучение) и что сейчас настраивается. Поэтому дисплей — не «полировка», а нужная часть интерфейса.
**Временно (этап 1):** виртуальный дисплей в Serial и в вебе, мигание светодиода, звуковой сигнал (пищалка). Раскладку управления строить так, чтобы ей можно было пользоваться без экрана.
**Позже:** родной LCD (этап 4) или OLED за окном дисплея. Реверс LCD поднять в приоритете, как только будет магнитола.

### 2026-11-03 — Платформа PlatformIO зафиксирована, USB CDC на родном USB
**Почему:** незафиксированная `platform = espressif32` в любой момент может обновиться и сломать сборку. Ветка 6.x — Arduino core 2.0.x, стабильная, все нужные библиотеки её поддерживают. `ARDUINO_USB_CDC_ON_BOOT=1` — Serial идёт через родной USB ESP32-S3 (разъём «USB» на DevKitC-1), а не через UART-мост.
**Альтернативы:** pioarduino (Arduino core 3.x) — новее, но не в официальном реестре PlatformIO; перейти, если понадобится что-то из core 3.x.

### 2026-11-03 — Порядок работы с Claude Code: одна сессия — одна задача
**Почему:** короткие сессии с понятным результатом, документы всегда актуальны. Правила — в `CLAUDE.md`.

### 2026-11-03 — Обновление прошивки по воздуху (OTA) — одним из первых пунктов этапа 1
**Почему:** ESP32 будет встроен в машину, разбирать консоль ради каждой прошивки не хочется. Если OTA есть с самого начала, временная установка в машину (1.11) и вся дальнейшая отладка идут без разборки.
**Как:** две OTA-области во flash (`default_8MB.csv`): новая прошивка пишется в свободный слот, при обрыве остаётся старая. ArduinoOTA из PlatformIO (ноутбук) + загрузка `.bin` через веб-страницу (телефон). Откат, если новая прошивка не подтвердила нормальный старт. Безопасный режим (только Wi-Fi + OTA) по кнопке при включении. Wi-Fi включается по запросу (комбинация кнопок), чтобы не мешать BLE. USB-кабель выведен в доступное место как запасной путь.
**Альтернативы:** только USB — нужна разборка; скачивание прошивки по ссылке (GitHub Releases через раздачу с телефона) — удобно, но сложнее, отложено; BLE OTA — медленно.
**Статус:** принято, реализация — этап 1.2.

### 2026-11-03 — Управление P8: перехват и повтор радиоканала пульта (ESP32 + nRF24L01+)
**Почему:** по разведке (этап 0.1) пульт AC-44F6 — не Bluetooth, а свой протокол 2.4 ГГц с приёмником внутри P8: отдельный 6-ногий радиочип, кварц 13.56 МГц, не виден ни в одном Bluetooth-скане. Дешёвые передатчики 2.4 ГГц обычно без шифрования и плавающего кода → пакеты можно записать и повторить. Многие китайские чипы (XN297, BK242x, Si24R1) совместимы с nRF24 по модуляции; модуль nRF24L01+ стоит €1–2 и потом же передаёт в машине.
**Альтернативы:** нажимать кнопки разобранного пульта транзисторами — владелец отверг как костыль; донгл nRF52840 (~€10) — гибче, если nRF24 не ловит; SDR (HackRF, ~€300) — крайний случай; BLE-клавиатура — проверяем отдельно (1.7), может дать дополнительные команды.
**Риски:** чип несовместим с nRF24 по модуляции/кадру; плавающий код (маловероятно).
**Статус:** заменено 2026-11-05 — пульт на 433 МГц, см. «Пульт на 433 МГц».

### 2026-11-05 — ESP32-S3 подтверждён после перехода на радиоканал
**Почему:** главный путь теперь nRF24 (не BLE-клавиатура), поэтому выбор пересмотрен. S3 остаётся: 8–16 МБ flash на типичных платах (две OTA-копии), больше всего свободных GPIO (матрица Toyota, энкодеры, nRF24, I2C, ШИМ, позже LCD), свой USB (прошивка/Serial, запасной вариант — USB HID), BLE 5, прошивка уже настроена.
**Альтернативы:** обычный ESP32 (WROOM-32) — обычно 4 МБ flash, меньше удобных GPIO, зато есть классический Bluetooth: держать в уме как дешёвый тест к 1.7, если P8 примет только BT Classic HID. ESP32-C5/C6 — Wi-Fi 6/5 ГГц и Zigbee/Thread нам не нужны (Zigbee не слышит протокол nRF24), меньше GPIO, нет USB-OTG, нужен Arduino core 3.x (у нас закреплён 2.0.x). C3 — мало GPIO, S2 — без Bluetooth, H2 — без Wi-Fi.
**Статус:** принято.

### 2026-11-05 — Raspberry Pi рассмотрен и отклонён
**Почему:** в машине — загрузка 20–40 с после ACC, порча SD-карты при пропадании питания, 1–3 Вт и нагрев, нет жёсткого реального времени для энкодеров. ESP32 стартует <1 с и спокойно переносит отключение. Как лабораторный инструмент (донгл nRF52840, SDR) хватает MacBook.
**Статус:** принято.

### 2026-11-05 — Плата для установки в машину: WROOM-1U без восьмеричной PSRAM
**Почему:** (1) температура — по памяти даташита Espressif, модули WROOM-1 с восьмеричной PSRAM (N8R8/N16R8) рассчитаны до 65 °C, без PSRAM или с N8R2 — до 85 °C, H-версии — до 105 °C; летом в торпедо на Кипре 65 °C мало. (2) металлический корпус магнитолы экранирует 2.4 ГГц → у ESP32 нужна внешняя антенна (WROOM-1U), у nRF24 — PA/LNA с SMA-антенной снаружи. (3) В машине только пайка, без Dupont.
**Альтернативы:** та же N16R8, что на столе — дешевле в логистике, но риск перегрева.
**Статус:** гипотеза. Температуры — проверить по даташиту перед покупкой; экранирование — проверить на магнитоле (2.7).

### 2026-11-05 — Железо для 1.6: mini nRF24L01+ без PA/LNA и без адаптеров
**Почему:** PA/LNA не было в наличии у продавца; на столе пульт в 10–50 см от модуля — чувствительности обычного хватает. Обычный nRF24 (~15 мА) питается от 3V3 платы, рядом 100 мкФ + 100 нФ. Mini-модуль выбран, чтобы взять всё у одного продавца; провода к нему припаять.
**Альтернативы:** модуль с гребёнкой 2×4 (без пайки); PA/LNA + адаптер AMS1117 от 5 В.
**Статус:** заменено 2026-11-05 — пульт на 433 МГц, nRF24 для него не годится (см. «Пульт на 433 МГц»).

### 2026-11-05 — Пульт на 433 МГц: перехват через CC1101 вместо nRF24
**Почему:** инструкция P8 — «Built-in 433MHZ AC-44F6 Remote receiver»; на внутренних фото FCC ([2AYLO-P5P8P9P10](https://fccid.io/2AYLO-P5P8P9P10)) приёмник подписан «433MHz-RX»; кварц пульта 13.56 МГц = 433.92 МГц / 32. nRF24L01+ работает только в 2.4 ГГц. CC1101 принимает и передаёт OOK/ASK/FSK, SPI, библиотеки для ESP32 есть.
**Альтернативы:** SYN480R + FS1000A (~€2, только OOK — не подойдёт, если пульт на FSK); RTL-SDR + `rtl_433` (~€30) — дорого для разовой проверки; Flipper Zero — тем более; E07-400T10S (есть на Кипре) — UART-модуль со своим MCU, сырой сигнал не снять.
**Модуль:** EBYTE E07-M1101D-SMA (CC1101, 433 МГц), 2 шт. — второй для проверки передачи без P8 и про запас.
**Риски:** модуляция/скорость неизвестны; возможен плавающий код.
**Статус:** принято, заказано.

### 2026-11-05 — Магнитола: Type B (86120-53021), замена — Type D
**Почему:** механизмы CD/MD/кассеты выбрасываем, поэтому выбор — по панели. Для меню нужен дисплей с буквами (`VOL 23`, `BRIGHT 5`, `LEARN`). У B и D — точечная матрица 5×7, у A — 7-сегментные цифры в фиксированных полях. У B есть кнопки TV и DISP, B, вероятно, чаще встречается. Подходят и неисправные («ジャンク»), если целы панель, LCD, кнопки и крутилки.
**Альтернативы:** D — равноценна, нет TV, вероятно, реже и дороже; A — только цифры и псевдобуквы; C — другая компоновка без двух больших крутилок, номер неизвестен.
**Доставка:** Japan Post на Кипр приостановлен, курьер ≈ €64 за одну магнитолу; сначала искать на Кипре, из Японии — по возможности две одной посылкой (см. `toyota-unit.md`).
**Статус:** принято. Буквенный LCD у B — по одному фото, подтвердить вживую.

### 2026-11-06 — Сигналы из штатной проводки: ILL, SPD, REV
**Почему:** CAN у SXE10 1998 нет, но дискретные провода дают то, чего не даст датчик: ILL/TAIL — надёжный признак «ночь» для ночного режима AA и яркости; SPD — громкость по скорости; REV — приглушение звука на заднем ходу (камера P8 включается сама).
**Альтернативы:** AVC-LAN (эмуляция CD-чейнджера) — не нужна, ESP32 стоит внутри панели; K-line ЭБУ — много усилий, мало пользы; реостат подсветки — у машины его нет; ручник (PKB) — не нужен.
**Статус:** принято. Наличие SPD/REV в разъёме магнитолы — гипотеза, проверить по распиновке.
